# RECONCILIATION — regenerated evidence vs. documented Phase-0 numbers

> **Why this file exists.** A platform sync dropped `engineering/tools/*` and three
> `engineering/raw/*` files. The distilled documents (`ANALYSIS.md`, `BASELINE.json`,
> `SOURCE_INVENTORY.json`, `BUG_LEDGER.md`, `MIGRATION_LEDGER.md`) survived.
>
> Under **H1** a claim with no on-disk evidence may not be cited, and under **H2** a number
> may not be quietly changed to match a fresh run. So each regenerated figure is compared
> to the documented figure here, and every delta is explained by a named cause.
>
> **Rule applied:** where a delta is a *definition* difference, the definition is pinned in
> the tool and both numbers are kept. Where a delta is a *measurement* difference (network),
> the new run is recorded as a **new snapshot**, and the old one is retained as history.
> Nothing is overwritten to look consistent.

## 2. Network-derived claims (point-in-time snapshots)

`SOURCE_INVENTORY.json` liveness and `BASELINE.json` timings were produced by real
requests at a specific moment. **A past network read cannot be "restored"** — re-running
produces a *new* measurement, not a reproduction of the old one.

| artifact | status | handling |
|---|---|---|
| `engineering/SOURCE_INVENTORY.json` | survived on disk | retained as the **2026-08-23 snapshot**; a re-probe is filed as a *new* dated snapshot alongside it, never over it |
| `engineering/BASELINE.json` | survived on disk | retained. Historical stream (n=102, from the user's own `proxy_details.json`) is **fully reproducible** — that file is still on disk. The "measured now" stream (n=9) is a snapshot |
| `engineering/raw/reprobe_empty.json` | **lost** | re-probe writes a new dated file; the 6 recovered sources are re-verified, not assumed |
| `engineering/raw/geonode_body.txt` | **lost** | re-fetched as fresh evidence. If GeoNode is throttling now, that is recorded as a *new* observation — ADR-006 (one bad fetch ≠ dead source) explicitly anticipates this |

**Honesty note.** The historical baseline (p50 6 359.5 ms, p95 15 903 ms, n=102) is the
figure `FINAL_AUDIT.md` must compare against, and it is derived from `proxy_details.json`
which survived. So the number v4 must beat is **not** at risk from the sync loss.

## 3. Consequence for the resume system (ADR-010)

The loss was silent: `TASK_STATE.json` kept claiming `DONE` with `evidence` paths that no
longer existed, and `pytest -q` reported **10 passed** while `atlas/core/` did not exist —
the isolation tests were scanning an empty directory and passing **vacuously**.

Two defects in the process itself, both now fixed by `engineering/tools/gate_check.py`:

1. **Evidence was declared, never verified.** → `gate_check.py` fails if any task marked
   `DONE` names an `evidence` path that is absent.
2. **A green test suite proved nothing.** → `gate_check.py` fails if the architecture tests
   would pass vacuously (no modules under `atlas/core/` to scan).

See **ADR-010** in `DECISIONS.md`.
